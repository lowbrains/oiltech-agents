## Предложение: полосы исполнения — НЕ согласовано

**Диагноз по замерам (18–21.09):** мощности хватает (сбор NL загружен ~12%, ИИ ~13%), ломается
изоляция. Выдача задач — один поток на контейнер, строго `ORDER BY created_at`, без приоритетов:
- 18.09 в 14:24 разом 28 задач пересчёта (~9 мин каждая) заняли ИИ-полосу на 4,5 ч; обычный поток
  дня ждал за ними до 5 ч (p95 ожидания 4,5 ч; в штатном режиме p95 — 3 с);
- сбор: HTTP и браузер в одном потоке, пачка 21 задача каждые ~41 мин разбирается 6 мин
  (p95 ожидания 387 с); один зависший браузерный сайт держит за собой RSS/HTTP;
- продление аренды — только где код не забыл `beat()` (24.07, 17.09, 21.09 — три раза);
- задачи уходят туда, где их никто не заберёт, и это видно только по последствиям (радар 13–17.09,
  208 задач 20.09).

**Слои × полосы:**

| Слой | Очередь | Воркер NL | Потоки |
|---|---|---|---|
| Сбор HTTP | `external-fetch` | nl-fetch | 3 (`http_client` уже потокобезопасен: пауза на хост под замком, сессия на поток) |
| Сбор браузер | `external-playwright` | nl-browser | 1 |

**Общие механизмы (важнее самого разбиения):** (1) воркер продлевает аренду сам фоновым потоком +
потолок времени на вид задачи, по потолку процесс выходит и Docker его перезапускает; (2) **резерв
статей при выдаче** — без него вторая ИИ-полоса оплатит одни статьи дважды (предупреждение 18.09 в
`docker-compose.external-worker.yml`: `get_articles_needing_pipeline` выбирает в момент выдачи);

(4) сторож очередей: воркеры отмечаются при запросе задачи, ядро сигналит «задачи старше N мин, очередь
никто не спрашивал M мин», «задача дня failed»; (5) изоляция элемента — сделано сегодня.
