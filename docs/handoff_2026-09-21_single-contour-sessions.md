## Сессия B — окно месяца и архивные модули (папка `oiltech-digest`, ветка `feat/monthly-window`)

**Цель:** в «Сигналах» виден только текущий месяц, прошлые открываются в архиве; архивные модули
убраны из меню, кода и контейнеров. Выкат — на РФ.

**Часть 1 — окно месяца.**
- **Правило одно и живёт в одном месте** — функция, которая отдаёт SQL-условие окна:
  - дата периода — `COALESCE(a.published_at, a.collected_at)`, как в `digest_candidates`;
  - нижняя граница — 1-е число текущего месяца; пока день месяца меньше `FEED_ROLLOVER_DAY`
    (5, по МСК), — 1-е число предыдущего;
  - по умолчанию применяется в `/api/articles` и в счётчиках ленты `/api/stats`.
- **Архив:** параметр `month=YYYY-MM` отдаёт прошлый месяц целиком с теми же остальными фильтрами. На
  фронте — переключатель «Текущий месяц / Архив» с выбором месяца.
- **`digest_candidates` не трогать:** он и так выбирает по месяцу.
- **Тесты с замороженными часами:**
  - 21.09 → только сентябрь;
  - 03.10 → сентябрь и октябрь;
  - 05.10 00:00 МСК → только октябрь;
  - статья без даты публикации попадает в месяц по дате сбора;
  - архив августа отдаёт август;
  - пометки и фильтры работают в архиве.
- **Ожидание на проде** (замер 21.09): видно 1 728 из 10 236, в архив уходит 8 508. После выката
  сверить запросом.
- **Агентный сайт** получит окно вместе с переключением (сессия D). Отдельно туда не переносить.

**Часть 2 — архивные модули.**
- **Инвентаризация:** каждый экран меню, роутер API, команду CLI, шаг планировщика и сервис compose
  отнести к «ядро / Германа / архив» с доказательством использования. Доказательства:
  - логи приложения за сутки:
    `docker logs oiltech_app --since 24h | grep -oE '"(GET|POST|PUT|PATCH|DELETE) /api/[^ ?]+' | sort | uniq -c`;
  - записи в базе за 30 дней;
  - ссылки из других модулей.
- **Кандидаты по замеру 21.09:**
  - «Аналитика для БРБ» и «Технологии» — статические превью из группы меню «Прототипы»;
  - контейнер `tasks` — копия приложения на `127.0.0.1:8010` под трекер `BACKLOG.md`, Caddy на неё не
    ведёт — вместе с маршрутами `/tasks` и `/api/backlog*`;
  - контейнер `docs` (`/help`) — проверить, открывает ли его кто-нибудь.
- **Список отправить владельцу одной таблицей и ждать утверждения до того, как что-то прятать.**
- **Как прятать:**
  - меню и маршрут фронта — убрать;
  - код — за флагом `ARCHIVED_MODULES` (по умолчанию модули выключены), не удалять;
  - сервис — в профиль compose `archive`;
  - работающий контейнер остановить и удалить, том не трогать; только с согласия владельца.

**Готово, когда:** тесты зелёные, на проде лента = сентябрь (число сверено), архив открывает август,
утверждённых модулей нет в меню, архивных контейнеров нет в `docker ps`.

## Сессия C — надёжность контура (папка `oiltech-digest`, ветка `feat/contour-reliability`)

**Цель:** задачи не дублируются, не теряются при выкате и не висят; РФ и NL сами сообщают о
расхождении. Пункты — по убыванию пользы.

1. **Мягкая остановка воркера.** Сейчас обработчика SIGTERM нет и `stop_grace_period` не задан.
   - по SIGTERM воркер перестаёт брать задачи и даёт текущим N секунд, чтобы закончить;
   - остальные сразу возвращаются в очередь новым вызовом release: статус queued, аренда снята,
     попытка не списывается, резерв статей снят или переиспользован;
   - `stop_grace_period` в compose — под N;
   - тест: SIGTERM посреди задачи → задача снова в очереди за секунды, а не через 600 с; для уже
     записанных статей ИИ повторно не вызывается.
2. **Один планировщик.**
   - `pg_try_advisory_lock` держится на весь цикл `docker-scheduler.sh`; второй экземпляр пишет
     строку в лог и ждёт;
   - профиль `pipeline` для `tasks`, `worker`, `playwright-worker`, `scheduler` — как в агентном
     репозитории;
   - тест: два процесса, шаги выполняет только один.
3. **Контракт версий.**
   - при `claim` воркер шлёт `X-Worker-Build` (git SHA, вшивается при сборке) и `X-Worker-Contract`
     (целое);
   - ядро хранит последнее значение каждого потребителя;
   - `check-lanes` и экран обслуживания показывают версии и тревогу `contract_mismatch`;
   - тест: воркер со старым контрактом вызывает тревогу.
4. **Пауза при пустой очереди:** 3 → 6 → … → 30 с, на первой задаче сбрасывается. Замер до и после;
   сейчас — 582 `claim` за 5 минут.
5. **Скрипты выката.**
   - `scripts/deploy-core.sh <сервисы…>`: fetch и reset; отказ при живых ИИ-арендах без `--force`;
     сборка и `up -d --no-deps` только названных сервисов; ожидание health; `check-lanes`;
   - `scripts/deploy-nl.sh` для владельца: воркеры пересобираются по одному, с мягкой остановкой из
     п. 1; в конце — версии потребителей из ядра.

**Не трогать:** полосу `external-agents` (её делает A) и границу Германа.
**Выкат:** ядро на РФ; NL — готовыми командами для владельца.
**Готово, когда:**
- тесты зелёные;
- после пересборки NL нет задач `running` с мёртвой арендой;
- `check-lanes` показывает версии всех четырёх потребителей;
- в простое не больше ~60 `claim` за 5 минут.
