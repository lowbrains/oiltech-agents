## Часть 2. Разделение на два репозитория

### Постановка поменялась после замера

Задача звучала как «отделить ветку Германа». **Ветки не существует.** Его агентная работа
была уже слита в `main` и работала на проде:

- PR #62 `codex/source-discovery-agent` → main 09.09 (`fe9f2bd`): **81 файл, +26 232 строки**
- сигнальный радар 12–13.09 (`3b2a880`, `d92eeba`, `5985671`): +4 609

**Резать по автору тоже нельзя.** У `electromop` 64 коммита с июня, и большинство — ядро
MVP-1: React admin, background jobs worker, Playwright ingestion, external worker routing,
digest export, тестовая инфраструктура.

**Связь агента с ядром — общая база, в обе стороны:**

```
агент → ядро:  signal_feedback_events.article_id    → articles
               source_quality_snapshots.source_id   → sources
               source_candidates.approved_source_id → sources
               source_candidate_articles.tag_id     → tags
               signal_evidence.article_id           → articles
ядро → агент:  background_jobs.agent_run_id         → agent_runs
```

Плюс 9 эндпоинтов из 90 в `api.py`, 268 упоминаний в `cli.py`, 133 в `repository.py`,
шаги `seed-signal-topics` и `enqueue-agent-loop` прямо в `scripts/docker-scheduler.sh`.

Решение владельца: агентный проект — **буквально копия, в которой пайплайн поэтапно
заменяется агентами**. Поэтому сделан форк полной историей, а не вырезание подсистемы.

### Что сделано

| | |
|---|---|
| Репозиторий | `lowbrains/oiltech-agents`, public, 272 коммита, авторство Германа (64 коммита) сохранено |
| Рабочая копия | `~/Desktop/oiltech-agents`, рядом с родителем |
| Содержимое | byte-identical MVP-1 на точке форка `d6ea6fc` — `git diff` пуст, кроме `CLAUDE.md` |
| Тесты | **598 из 598 зелёные** (`.venv` от MVP-1, локальный Postgres через colima) |
| `CLAUDE.md` | переписан: чем репозиторий отличается, что агентное, какая развязка не сделана |

`lowbrains` не может создавать репозитории в неймспейсе `electromop` — это личный аккаунт
Германа, не организация. Перенос к нему — отдельным шагом, если нужно.

**Remote'ы разведены односторонне:** в `oiltech-agents` есть `mvp1` (fetch, push закрыт
заглушкой) — чтобы тянуть сюда фиксы MVP-1. Из `oiltech-digest` remote на агентный
репозиторий **убран**, чтобы случайный push не перезаписал агентный `main`.

### Чего не сделано намеренно

- **Своя БД и поддомен.** До этого агентный проект деплоить нельзя: два деплоя по одной
  схеме удвоят класс бага от 13.09 (сид воскрешал выключенные критерии, порядок блоков в
  `schema.sql` load-bearing). `docker-compose.yml` и `.env.example` в новом репозитории
  унаследованы от MVP-1 и указывают на ту же базу и порты.
- **Вырезание агента из `oiltech-digest`.** Прод стоит на коде с агентом, Виктор смотрит
  радар ежедневно. Резать имеет смысл только после того, как агент поедет из нового места.

### Побочное, но полезное

- **Единственное падение теста** в новом репозитории (`test_discover_signals_filters_reject_title_even_when_maturity_watch`)
  — отсутствующий `.env`, он в `.gitignore` и клоном не переносится. С ключом из MVP-1
  тест проходит. Но сам по себе тест **не герметичен**: требует живой `OPENAI_API_KEY` и
  ходит в сеть (`200×2, 403×1` за прогон). В CI он упадёт и может тратить деньги.
- **Desktop под iCloud, и это ломает git.** `fileproviderd` уходит в 30–58% CPU:
  `git clone --no-hardlinks` полз 4 минуты до 2 МБ из 19 и был снят, `--local` прошёл
  (объекты git неизменяемы, жёсткие ссылки безопасны). Сбор 598 тестов — **131 секунда
  на одних импортах**; я дважды принял это за зависание и убивал процесс. Признак живого
  ожидания: 0% CPU при 1,5 с накопленного CPU-времени. `~/Documents` тоже под iCloud.
- `timeout` на macOS нет (нужен `gtimeout`); `tail` в конце конвейера копит вывод до EOF,
  поэтому прогресс через него не виден — писать надо прямо в файл.
