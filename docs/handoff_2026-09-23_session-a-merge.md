## Ловушки и ложные версии

- **«Вернуть 22 файла Германа — и граница цела»** — ложно. Молча теряются и строки общих файлов, и
  «хвосты», вычищенные после выноса (`b24adca`). Проверка на будущее — удалённые строки против
  агентного `main`:
  `git diff -U0 origin/main -- . ':(exclude)docs/**' | grep '^-' | grep -iE 'signal|discover|candidate|agent|radar|brave|serpapi'`.
  Слово `candidate` в сборе — это `CandidateLink` ядра, шум.
- **422 вместо 200** — признак пропавшей Pydantic-модели: при `from __future__ import annotations`
  FastAPI молча делает тело query-параметром. Поймали только агентные тесты `test_api`.
- **`git merge -s ours` → «сбой при выполнении stash»** сразу после первого слияния. Причина — racy-индекс:
  файл и индекс записаны в одну секунду, и `git stash create` без обновления индекса видит изменения.
  Лечится `git update-index --refresh` перед следующим слиянием.
- **Два теста кодируют имя сервиса приложения в compose.** `test_collection_robustness` из MVP-1 ждал
  `app` — переписан без привязки к имени. `test_bare_compose_up_starts_only_core_services` (граница)
  ждёт `agents-app` — в D при смене идентичности его придётся менять.
- **Дрейф схемы.** У `signal_feedback_events` колонки `signal_id`, `signal_evidence_id`,
  `duplicate_of_signal_id` объявлены в `CREATE TABLE` без `REFERENCES`, а `ALTER … ADD COLUMN IF NOT
  EXISTS … REFERENCES` вешает ключ только на старых базах. Итог: в основной и агентной базах ключи есть,
  в базе с нуля — нет.
- **Выдача фильтрует только по очереди.** Застрявшая в `external-ai` старая задача радара уйдёт в
  `nl-ai-1` с сырым payload.
- **Инструменты.**
  - `preview_start` читает `launch.json` не из worktree — живую проверку делали через `TestClient`.
  - Сторож worktree отказывает сложным командам с git (подстановки, heredoc): проверки — скриптами
    из скретчпада.

  `normalize.parse_html`, `BACKGROUND_JOB_INLINE`, таблица сборщиков payload) — двойной счёт.
